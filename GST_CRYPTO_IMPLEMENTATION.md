# GST Crypto Implementation Guide

This document explains the cryptographic implementation used for GST Portal authentication via Alankit API, following GSTN's security requirements.

## Overview

The GST Portal requires end-to-end encryption for all API communications using a combination of RSA and AES encryption:

- **RSA (2048-bit)**: Used to encrypt the AppKey
- **AES-256-ECB**: Used for encrypting request/response payloads

## Architecture

\`\`\`
┌─────────────────────────────────────────────────────────────┐
│                    Authentication Flow                       │
└─────────────────────────────────────────────────────────────┘

1. Generate AppKey (32 bytes, random)
   ↓
2. Encrypt AppKey with GST Public Key (RSA/PKCS1)
   ↓
3. Send encrypted AppKey to GST Portal
   ↓
4. Receive encrypted SEK (Session Encryption Key)
   ↓
5. Decrypt SEK using AppKey (AES-256-ECB)
   ↓
6. Use SEK to encrypt/decrypt all API requests/responses
\`\`\`

## Key Components

### 1. AppKey Generation
\`\`\`typescript
// Generate random 32-byte key (AES-256)
const appKey = crypto.randomBytes(32).toString("base64")
\`\`\`

### 2. RSA Encryption
\`\`\`typescript
// Encrypt AppKey with GST's public key
const encryptedAppKey = crypto.publicEncrypt(
  {
    key: gstPublicKeyPem,
    padding: crypto.constants.RSA_PKCS1_PADDING
  },
  Buffer.from(appKey, "base64")
)
\`\`\`

### 3. AES Encryption/Decryption
\`\`\`typescript
// AES-256-ECB encryption
const cipher = crypto.createCipheriv("aes-256-ecb", keyBytes, null)
cipher.setAutoPadding(true)
let encrypted = cipher.update(plainText, "utf8", "base64")
encrypted += cipher.final("base64")
\`\`\`

## Key Chain

The GST Portal uses a hierarchical key structure:

1. **AppKey**: Generated by client, encrypted with GST public key
2. **SEK (Session Encryption Key)**: Returned by GST Portal, encrypted with AppKey
3. **API EK (Encryption Key)**: Used for specific API calls, encrypted with SEK

### Key Decryption Chain

\`\`\`
AppKey (your generated key)
  ↓ decrypt
SEK (from GST Portal)
  ↓ decrypt
API EK (for specific operations)
  ↓ decrypt/encrypt
Payload data
\`\`\`

## Implementation Files

### Core Crypto Module
**File**: `lib/gst-crypto-helper.ts`

Contains all cryptographic functions:
- `generateAppKey()` - Generate random 32-byte key
- `encryptAppKeyRSA()` - Encrypt AppKey with GST public key
- `aesEncrypt()` - Encrypt data with AES-256-ECB
- `aesDecrypt()` - Decrypt data with AES-256-ECB
- `decryptAuthSEK()` - Decrypt SEK using AppKey
- `decryptApiEK()` - Decrypt API key using SEK
- `encryptPayload()` - Encrypt request payload
- `decryptPayload()` - Decrypt response payload

### GST API Client
**File**: `lib/alankit-gst-api.ts`

Integrates crypto functions with API calls:
- Generates and encrypts AppKey during OTP request
- Decrypts SEK during OTP verification
- Provides encrypted API call wrapper

## Storage Strategy

### Redis Keys

1. **Temporary Session** (5 minutes)
   - Key: `gst:session:{GSTIN}`
   - Value: AppKey (Base64)
   - Purpose: Store AppKey between OTP request and verification

2. **Auth Token** (6 hours)
   - Key: `gst:token:{GSTIN}`
   - Value: Authorization token
   - Purpose: Authenticate API requests

3. **Session Encryption Key** (6 hours)
   - Key: `gst:sek:{GSTIN}`
   - Value: SEK (Base64)
   - Purpose: Encrypt/decrypt API payloads

### Security Considerations

✅ **DO**:
- Generate new AppKey for each authentication session
- Store AppKey only in Redis with short expiration
- Delete AppKey immediately after SEK is obtained
- Keep SEK in Redis with 6-hour expiration
- Use HTTPS for all API communications

❌ **DON'T**:
- Store AppKey in logs or client-side
- Reuse AppKey across sessions
- Store SEK in localStorage or cookies
- Print encryption keys in production
- Disable encryption for debugging

## API Flow Examples

### 1. Request OTP

\`\`\`typescript
// Generate session with encrypted AppKey
const { appKey, encryptedAppKey } = createGSTSession()

// Send to GST Portal
POST /authenticate
{
  "action": "OTPREQUEST",
  "username": "29AABCT1234F1Z5",
  "app_key": encryptedAppKey  // RSA encrypted
}

// Store AppKey temporarily in Redis
await redis.setex(`gst:session:{GSTIN}`, 300, appKey)
\`\`\`

### 2. Verify OTP

\`\`\`typescript
// Retrieve stored AppKey
const appKey = await redis.get(`gst:session:{GSTIN}`)

// Send OTP
POST /authenticate
{
  "action": "AUTHTOKEN",
  "username": "29AABCT1234F1Z5",
  "otp": "123456"
}

// Response contains encrypted SEK
const response = {
  "status_cd": "1",
  "data": {
    "auth_token": "eyJ...",
    "sek": "encrypted_sek_base64"  // AES encrypted with AppKey
  }
}

// Decrypt SEK
const sek = decryptAuthSEK(response.data.sek, appKey)

// Store auth token and SEK
await redis.setex(`gst:token:{GSTIN}`, 21600, response.data.auth_token)
await redis.setex(`gst:sek:{GSTIN}`, 21600, sek)

// Delete temporary AppKey
await redis.del(`gst:session:{GSTIN}`)
\`\`\`

### 3. Make Encrypted API Call

\`\`\`typescript
// Retrieve auth token and SEK
const authToken = await redis.get(`gst:token:{GSTIN}`)
const sek = await redis.get(`gst:sek:{GSTIN}`)

// Encrypt request payload
const payload = { gstin: "29AABCT1234F1Z5", ret_period: "042024" }
const encryptedPayload = encryptPayload(payload, sek)

// Make API call
POST /gstr2b
Headers: { Authorization: `Bearer ${authToken}` }
Body: { data: encryptedPayload }

// Decrypt response
const decryptedResponse = decryptPayload(response.data, sek)
\`\`\`

## Testing

### Sandbox Environment

The sandbox uses the same encryption as production. Test with:

\`\`\`typescript
// Enable debug mode to see AppKey
const session = createGSTSession(undefined, true)
console.log("AppKey:", session.appKey)
console.log("Encrypted:", session.encryptedAppKey)
\`\`\`

**⚠️ WARNING**: Only enable debug mode in sandbox. Never in production!

### Verification Steps

1. ✅ AppKey is 32 bytes (44 characters in Base64)
2. ✅ Encrypted AppKey is 512 characters (RSA-2048)
3. ✅ SEK is successfully decrypted (no errors)
4. ✅ Auth token is received after OTP verification
5. ✅ Encrypted API calls return valid responses

## Error Handling

Common encryption errors and solutions:

| Error | Cause | Solution |
|-------|-------|----------|
| "Invalid key length" | Wrong AppKey size | Regenerate with 32 bytes |
| "Decryption failed" | Wrong key used | Verify key chain order |
| "Invalid padding" | Corrupted encrypted data | Check Base64 encoding |
| "Public key error" | Wrong RSA key format | Use PEM format |
